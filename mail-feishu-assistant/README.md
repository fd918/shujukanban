# 飞书邮箱审批助手

这是一个跑在 Mac 本地的助手，用于定时巡检飞书邮箱，把疑似需要你处理的邮件发到飞书机器人，然后根据你在飞书里的指令回复邮件。

第一版不接 AI，只做规则识别和按原文回复。

## 功能范围

- 定时分页读取飞书邮箱收件箱今天的邮件
- 每天09:15自动读取“外卖业务订单推广统计”邮件中的美团、淘宝闪购、京东万单和京东四川云瞻附件，并同步流失看板
- 按关键词识别疑似需要处理的邮件
- 通过飞书机器人通知你
- 支持你在飞书里发指令：

```text
回复 同意。
回复全部 同意，请继续处理。
忽略
发送 张三
主题：测试邮件
内容：
这里写邮件正文
确认发送
```

也支持换行：

```text
回复全部
同意开通
```

说明：

- `回复`：只回复原发件人
- `回复全部`：回复原发件人，并抄送原邮件里除你以外的收件人和抄送人
- 两种回复都会保留原邮件会话关系，并引用原邮件的富文本正文和正文内嵌图片
- 原邮件的普通附件不会重复发送，回复历史中会显示附件名称；收件人可在原邮件会话中查看附件
- `忽略`：本地标记为忽略，不发送邮件
- `发送`：新建邮件草稿，确认后发出
- 新建发送草稿后，可以直接把图片、文档或表格发给机器人，机器人会把附件加入当前草稿
- `查看待处理`：查看当前自己所有未处理邮件的列表，再按编号选择某一封详情
- 如果同时有多封待处理邮件，仍可带邮件编号，例如 `M20260627-001 回复 同意。`
- 如果发送了无法识别的内容，机器人会返回可用指令清单。

## 配置文件

配置文件放在本目录：

```text
项目目录/.env
```

如果还没有 `.env`，先复制模板：

```bash
cd "你的项目目录/mail-feishu-assistant"
cp .env.example .env
```

然后用文本编辑器填写：

```env
FEISHU_APP_ID=你的飞书应用 App ID
FEISHU_APP_SECRET=你的飞书应用 App Secret
FEISHU_REDIRECT_URI=http://127.0.0.1:3456/callback
```

不要把真实 `.env` 发给别人，也不要提交到 Git。

当前公网 OAuth 回调地址：

```text
https://tanwenjie-mail-assistant.loca.lt/callback
```

需要在飞书开放平台后台的重定向 URL 中配置这个地址。这个地址由本机 `localtunnel` 隧道提供，适合先跑通多人授权；如果后续要长期稳定使用，建议换成自己的固定 HTTPS 域名。

## 需要的飞书后台配置

你已经完成了这一步，这里保留为复查清单。

1. 飞书开放平台创建企业自建应用
2. 开启机器人能力
3. 事件订阅方式选择长连接
4. 添加事件：

```text
im.message.receive_v1
```

5. 添加卡片回调：

```text
card.action.trigger
```

说明：邮件提醒使用飞书消息卡片。`回复`、`回复全部`、`忽略`、`查看待处理` 按钮依赖这个卡片回调。

如果点击按钮时飞书提示：

```text
该应用尚未配置卡片回调，一键完成配置后即可使用
```

说明飞书客户端还没有把卡片点击事件发给本地助手，不是邮件回复代码没有执行。处理方式：

1. 进入飞书开放平台
2. 打开当前企业自建应用
3. 进入“事件与回调”或“卡片回调”相关配置页
4. 添加或启用卡片回调事件 `card.action.trigger`
5. 事件订阅方式继续使用“长连接”
6. 保存后发布应用新版本
7. 回到飞书机器人单聊，重新发送 `巡检`，用新发出来的卡片测试按钮

只有发布后的应用版本生效，旧卡片可能仍然不能点，建议用新巡检生成的新卡片测试。

6. 开通邮箱权限：

```text
mail:user_mailbox:readonly
mail:user_mailbox.folder:read
mail:user_mailbox.message:readonly
mail:user_mailbox.message.subject:read
mail:user_mailbox.message.body:read
mail:user_mailbox.message.address:read
mail:user_mailbox.message:send
```

直接发送邮件并添加附件时，机器人会读取用户发给机器人的消息资源。飞书后台需要保持机器人能力开启，并订阅消息事件：

```text
im.message.receive_v1
```

代码使用的是“获取消息中的资源文件”接口下载用户发来的图片、文档和表格；不要改成“下载图片”或“下载文件”接口，因为那两个接口只能下载机器人自己上传的资源。

多人共用时，还需要开通通讯录权限，用来校验“发消息的人只能绑定自己的企业邮箱”：

```text
contact:contact.base:readonly
```

7. 配置重定向地址：

```text
http://127.0.0.1:3456/callback
```

8. 发布应用新版本

## 第一次授权

在 macOS 终端执行：

```bash
cd "你的项目目录/mail-feishu-assistant"
npm run auth
```

正常结果：

- 终端会打印一个飞书授权链接
- 浏览器打开该链接
- 同意授权
- 页面显示授权成功
- 本地生成：

```text
data/tokens.json
```

这个文件包含邮箱授权令牌，是敏感文件，不要发给别人。

## 启动助手

授权完成后执行：

```bash
cd "你的项目目录/mail-feishu-assistant"
npm run start
```

正常结果：

- 终端显示“邮件审批助手已启动”
- 程序会先做一次启动巡检
- 后续按个人配置的巡检时间段，在整点自动巡检

默认巡检时间：

```text
每天 08:00 到 22:00，每小时一次
```

流失看板邮件表格同步默认在每天 `09:15` 检查一次。只下载以下四张精确附件，避免把拼好饭、普通京东订单等其他业务重复计入：

```text
美团订单-数据统计-YYYYMMDD09.xlsx
淘宝闪购订单-数据统计-YYYYMMDD09.xlsx
京东订单-万单-数据统计-YYYYMMDD09.xlsx
京东订单-四川云瞻（非密令业务）-数据统计-YYYYMMDD09.xlsx
```

四张表都只读取“平台联盟”子表，并自动排除邮件当天的未完整数据。如果当天邮件未收到或附件不完整，会保留上一份数据并写入未更新原因和滞后天数。手动验证可在本目录执行：

```bash
npm run sync-churn
```

本地结果保存在主项目的 `data/private/mail-churn-dashboard.json`，该目录不会提交到 Git。同步服务器时，把完整请求头统一放在本目录 `.env` 的 `MAIL_CHURN_SERVER_REQUEST_HEADERS`；以后令牌变化只整体替换这一段 JSON，不要分别改代码里的 Authorization 或其他请求头。真实 `.env`、令牌和飞书授权文件都不得提交或出现在公开截图中。

定时巡检完成后，机器人会把本次接口读取封数、今日邮件封数、今日已处理封数、今日待处理封数、新发现待处理封数发给对应绑定用户。巡检失败时也会发送失败原因。

## 绑定飞书通知目标

启动助手后，在飞书里打开机器人单聊。

每个人都只需要发送：

```text
绑定我
```

机器人会自动读取发送人的飞书通讯录企业邮箱并绑定。正常结果：

```text
已绑定当前聊天和邮箱：name@yunzhanxinxi.cn
后续你发送“巡检”会检查这个邮箱。
```

如果确实需要调试，也支持手动指定邮箱：

```text
绑定邮箱 name@yunzhanxinxi.cn
```

手动指定邮箱也会校验：只能绑定发送人自己的通讯录邮箱。

如果想手动巡检一次，给机器人发送：

```text
巡检
```

助手会回复本次接口读取封数、其中今日邮件封数、今日已处理数量、今日待处理数量，以及新发现待处理邮件数量。

如果想查看当前所有还没处理的邮件，发送：

```text
查看待处理
```

机器人会先发送待处理列表，不会一次性刷出所有详情。你可以：

```text
1
```

或：

```text
查看待处理 1
```

机器人会显示第 1 封邮件详情。详情卡里可以继续点 `回复全部`、`回复`、`忽略` 或 `查看待处理`。

## 个人配置

每个人可以查看和修改自己的巡检关键词。

查看当前配置：

```text
查看配置
```

机器人会返回：

- 绑定状态
- 绑定邮箱
- 授权状态
- 授权邮箱
- 授权更新时间
- 当前巡检关键词
- 当前定时巡检时间

设置自己的关键词：

```text
设置关键词 审批、请处理、同意、续期
```

也支持换行：

```text
设置关键词
审批
请处理
同意
续期
```

重置为默认关键词：

```text
重置关键词
```

说明：

- 关键词按个人保存
- `巡检` 和定时巡检都会使用个人关键词
- 没有设置个人关键词时，使用 `.env` 里的默认关键词
- 关键词之间可以用中文顿号、中文逗号、英文逗号或换行分隔

设置自己的定时巡检时间：

```text
设置巡检时间 8-12,14-18,20-22
```

也可以只设置几个固定整点：

```text
设置巡检时间 9,14,19,22
```

重置为默认时间：

```text
重置巡检时间
```

说明：

- 巡检时间按个人保存
- 支持多个时间段，时间段之间可以用中文逗号、英文逗号、顿号或换行分隔
- 时间按小时设置，例如 `8-12` 表示 08:00、09:00、10:00、11:00、12:00 都会巡检
- 手动发送 `巡检` 不受时间段限制

多人共用说明：

- 可以共用同一个机器人
- 每个人在机器人单聊里发送 `绑定我`，系统自动绑定他的通讯录企业邮箱
- 每个人发送 `巡检` 时，只检查自己绑定的邮箱
- 每封待处理邮件会记录归属用户，其他人不能拿编号代替回复
- 定时巡检会逐个检查已绑定用户的邮箱，并分别发到各自单聊
- 当前版本会通过飞书通讯录校验：发消息的人只能绑定自己的企业邮箱
- 如果绑定时报“无法读取你的飞书通讯录邮箱”，请检查应用是否开通并发布了 `contact:contact.base:readonly`

## 直接发送邮件和附件

## 用户授权

同事如果需要用自己的邮箱自动回复邮件，需要先在机器人里发送：

```text
授权我
```

机器人会返回飞书授权链接。同事打开链接并同意后，授权会回到：

```text
https://tanwenjie-mail-assistant.loca.lt/callback
```

如果打开授权链接后先看到 `localtunnel` 安全确认页，不是飞书授权失败。按页面提示操作：

1. 找到页面上的 `This tunnel is hosted by` 后面的 IP 地址
2. 在 `IP Address` 输入框里填这个 IP
3. 点击 `Continue`
4. 继续完成飞书授权

机器人发送授权链接时，也会尽量附带当前可尝试填写的 IP。

授权成功后，系统会把授权保存到该用户自己的记录下。之后该用户回复邮件时，会使用他自己的邮箱授权发信。

说明：

- 电脑关机后服务不会运行
- 重新开机并登录 Mac 后，`launchd` 会自动启动服务
- 如果你发现没有提醒，双击桌面入口选择“查看服务状态”或“重启服务”

## 回复邮件

机器人发现待处理邮件后，会发卡片。你可以直接点击卡片按钮：

- `回复全部`：进入等待输入状态，然后你在聊天框发送回复内容
- `回复`：进入等待输入状态，然后你在聊天框发送回复内容
- `忽略`：直接标记忽略
- `查看待处理`：显示当前自己所有未处理邮件的列表，再按编号选择详情

点击 `回复全部` 或 `回复` 后，机器人会提示等待输入。此时你直接发送：

```text
同意开通
```

机器人会把这段内容发到刚才那封邮件。如果不想继续，发送：

```text
取消回复
```

正文和图片显示规则：

- 邮件正文默认按全文发送，不再只显示摘要
- 正文超过飞书单张卡片限制时，会自动拆成多张卡片，例如 `第 1/2 部分`、`第 2/2 部分`
- 邮件里的内嵌图片会尽量上传到飞书卡片中展示，默认最多展示前 6 张
- 普通附件会显示附件数量和文件名；如果图片下载失败，会记录日志，但不会影响文字正文和按钮操作

也仍然支持旧的文字指令，例如：

```text
发现一封可能需要你处理的邮件：M20260627-001
发件人：杨凤琴 <yangfengqin@yunzhanxinxi.cn>
主题：客服中心团队申请续期代理系统

正文全文：
ID：95148951，客服中心团队申请续期代理系统，期限1年，用于测试及日常处理用户咨询...
```

你可以回复：

```text
回复 同意。
```

或：

```text
回复全部
同意，请继续处理。
```

发送成功后，机器人会回你：

```text
M20260627-001 已回复：同意。
```

## 直接发送邮件

直接发邮件使用两步确认，避免误发。

第一步，发送邮件内容：

```text
发送 @张三 @李四
主题：测试邮件
内容：
这里写邮件正文
```

也可以直接写邮箱：

```text
发送 zhangsan@example.com,lisi@example.com
主题：测试邮件
内容：
这里写邮件正文
```

机器人会先返回草稿预览和编号，例如：

```text
已生成待发送邮件草稿：S20260628-001
```

第二步，确认发送：

```text
确认发送
```

说明：

- 飞书机器人私聊里不一定方便 `@同事`，推荐直接写中文姓名或邮箱
- 飞书 `@同事` 指在飞书输入框里输入 `@` 后选择那个人，不是只打出 `@姓名`
- 也可以直接写中文姓名或邮箱地址
- 中文姓名只有匹配到唯一一名同事时才会生成草稿；如果重名，会提示改用 `@同事` 或邮箱
- 如果需要附件，先生成草稿，再把图片、文档或表格直接发给机器人；机器人会把附件添加到最近的待发送草稿
- 附件添加完成后，再发送 `确认发送`
- 如果同时有多个草稿，也可以用 `确认发送 S20260628-001` 指定某个草稿

## 安全开关

如果你想先测试，不真正发送邮件，把 `.env` 改成：

```env
ALLOW_SEND_EMAIL=false
```

改完需要重启助手。此时你发回复指令，助手只会把“拟发送内容”发回飞书，不会真的发邮件。

确认稳定后再改回：

```env
ALLOW_SEND_EMAIL=true
```

## 调整识别关键词

在 `.env` 中修改：

```env
ACTION_KEYWORDS=请谭总,谭总,审批,请审批,同意,请同意,请处理,请确认,确认,申请,批准,续期
NOISE_KEYWORDS=数据详见附件,每日汇总,数据统计,数据日报,验证码,安全提醒,sign up code
```

中文说明：

- `ACTION_KEYWORDS`：出现这些词时，更可能通知你
- `NOISE_KEYWORDS`：出现这些词时，降低通知概率，避免日报和验证码刷屏

改完需要重启助手。

## 常见问题

### 授权失败

优先检查：

- `.env` 中 `FEISHU_APP_ID` 是否正确
- `.env` 中 `FEISHU_APP_SECRET` 是否正确
- 飞书后台重定向 URL 是否完全等于 `http://127.0.0.1:3456/callback`
- 应用权限修改后是否已经重新发布

### 收不到机器人通知

优先检查：

- 助手是否正在运行
- 飞书后台是否订阅了 `im.message.receive_v1`
- 是否已给机器人发送 `绑定我`
- 应用是否已发布

### 邮件发送失败

优先检查：

- 是否完成 `npm run auth`
- 邮箱权限是否开通了 `mail:user_mailbox.message:send`
- 应用权限修改后是否重新发布
- `.env` 里的 `ALLOW_SEND_EMAIL` 是否为 `true`
